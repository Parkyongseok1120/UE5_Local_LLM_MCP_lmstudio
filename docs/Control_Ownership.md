# Control ownership and recovery contract

This document records the runtime owner of state that crosses Python task control, the Node Agent MCP, and the LM Studio context compactor. A copy is never authority merely because it is newer in wall-clock time; the listed CAS identity and invalidation rule decide whether it can be used.

| State | Authoritative owner | Derived copies | Persistence and CAS key | Invalidation and recovery rule |
|---|---|---|---|---|
| Task status and mode | `scripts/task_api.py` task `state.json` | Agent tool payloads; Compactor control summary | Atomic task state revision; `taskSessionId` | Only Python task transitions may complete/cancel it. Corrupt or mismatched identity fails closed. |
| Active slice and plan revision | Python task state | Node route authorization; Compactor checkpoint | `taskSessionId`, `planRevision`, `activeSliceId` | Replan/slice advance rotates route and authorization. Old slice arguments are rejected. |
| Route hash and control epoch | Python `phase_tool_router.py` projection committed by `task_api.py` | Node `task-control-transition.js` parity projection; Compactor `serverControl` | `taskSessionId`, `controlEpoch`, `controlFingerprint`, `routeHash` | Higher epoch wins. Same-epoch fingerprint mismatch fails closed; an older control cannot resurrect a route. |
| Recovery obligation and build blocker/recovery | Python task state | Node recovery envelopes; Compactor semantic/control summaries | Recovery fingerprint plus task/slice/mutation generation | Evidence must satisfy the exact server-owned tool and arguments. Mutation, replan, or authoritative recovery transition replaces the obligation. |
| Repository audit frontier | Python `repoAuditLedger` | Public bounded status summary; Node direct-read advancement; Compactor exact required tool | Inventory hash, analysis version, cursor, per-path content hash | A changed content hash invalidates only that entry. Restart resumes the cursor; synthesis is rejected until all bounded entries are analyzed or excluded. |
| Routed RAG analysis outcome | Python `task_commit_routed_analysis_outcome` in canonical task `state.json` | RAG MCP structured result; Compactor server control | Task/route authorization, control epoch, argument hash, bounded 32-entry outcome ledger | Success and failure use the same commit transaction. Missing/unreadable RAG marks the capability unavailable, skips remaining index-dependent actions, and issues a direct-source recovery route. Replan clears the capability observation; the historical ledger remains bounded. |
| RAG index data | Installer-managed `<state-home>/indexes/<namespace>/rag.sqlite`, or an explicit user-selected absolute path | Shared workspace config, MCP `--index`, `UNREAL_RAG_INDEX_PATH` | Absolute path plus query-level `chunks`/`chunks_fts` readiness | Versioned packages never own the default installed index. Upgrade hard-links or copies the newest query-ready prior index into stable ownership. A requested build must end query-ready; a skipped build reports explicit degraded readiness when no usable index exists. |
| Mutation generation and disk receipt | Node `mutation-generation.js` state, reconciled with filesystem hashes | Python task generation/checkpoint; Compactor mutation generation | Project/task scope, mutation generation, pre/post hashes | A successful write advances generation. Crash recovery accepts the exact post-image, restores the exact pre-image, or marks reconciliation required on CAS/ABA conflict. |
| Static validation checkpoint | Python task checkpoint after Node validator result | Node validation guard; Compactor build state | Task/slice/mutation generation and validation status/hash | Mutation or slice transition invalidates proof. Build is illegal without a passed current-generation checkpoint. |
| Build attempt/failure guard | Node `workflow-loop-guard.js` | Build response and Python recovery obligation | Task/project/mutation generation; command/diagnostic fingerprints | Same-generation blind rebuild is blocked. Evidence plus repair mutation creates a fresh generation and attempt budget. |
| Successful-build bookkeeping | Node durable workflow guard through Python acceptance and MCP response replay | Python build proof/history after acceptance | Bookkeeping transaction id, build-attempt id, proof digest, exact build tuple, mutation generation | UBT success is not task completion. If Python persistence or the MCP response fails, replay the immutable receipt without rerunning UBT. Keep the accepted receipt until a new mutation generation invalidates that build scope. |
| Build proof and final task completion | Python `task_complete_after_successful_build` | Node response; Compactor terminal control | Exact `Built` (`BuiltFresh`) level, content-addressed proof digest, task/project/build tuple, slice, static checkpoint and mutation generation | Up-to-date-without-compile, stale-during-build, unverified, missing-digest, wrong-project, wrong-tuple, or wrong-generation proof is rejected. Automation cannot upgrade a weak compiler proof. |
| Mutation transaction journal | Node `transaction-journal.js` | Python rollback checkpoint binding | Transaction id, task/project/generation, per-file pre/post hash | Startup resolves to accepted, rolled back, or reconciliation-required. External post-write changes are never overwritten. |
| Compactor checkpoint and semantic blocker | Compactor checkpoint store | Model-facing compact system summary | Conversation/session identity, source-history hash, checkpoint generation, monotonic store revision | Session write lock plus revision CAS rejects a stale concurrent generator. New goal, successful bound transition, or newer server control invalidates semantic copies without resetting the storage revision. |
| Prediction lifecycle | Compactor generator | UI fragments and telemetry | Objective/task identity, control epoch, output digest | Buffered final/tool output is discarded on truncation, abort, model-fence change, or failed durable prepare. |
| Reasoning execution policy | Compactor generator for each prediction attempt | Checkpoint and telemetry | Policy fingerprint, model identifier, LM Studio instance reference, effort and phase | One resolved policy drives `model.respond`. Exact tool serialization phases disable thinking. Qwen 3.8 27B fails closed without an observable instance reference. `transportConfigured` is distinct from `backendApplied=unknown` and `backendObserved=false`; SDK-unobservable state is never reported as observed. |
| Synthesis lifecycle and semantic completion | Python synthesis ACK is completion authority; Compactor owns UI delivery | Compactor prepared/commit-sent/ACKed/delivered checkpoint | Task authorization, objective hash, control epoch/fingerprint, mutation generation, output digest and transaction id | No final text is delivered before exact ACK. ACK replay is idempotent; failed delivery resumes from durable ACKed output without a new model call or duplicate completion. |

The Python and Node control-transition projections are tested from the same adversarial state corpus. Any field added to an authoritative transition must be added to that parity corpus or deliberately classified as a transport-only derived field. LM Studio tool-result persistence is tri-state: explicit success, explicit failure, or unknown. Unknown remains usable by legacy evidence extraction as non-failing, but it can never satisfy the exact-tool replay-suppression guard; only affirmative success may do that.
