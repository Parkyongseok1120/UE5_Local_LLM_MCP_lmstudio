# 멀티플레이 공통 판단

적용: 네트워크 게임의 입력·판정·동기화·시간·연결 수명.
범위: 공통 개념. 서버 권한, Host/Listen Server, 분산 권한 중 프로젝트의 방식부터 확인한다. [근거](sources.md#network)

<!-- guidance-section: authority -->
## 권한과 상태

- 로컬 제어, 연결 소유권, 상태 확정 권한을 구분한다.
- 입력 의도 → 네트워크 전달 → 권한 측 규칙 검사 → 결과 확정 → 복제·표시의 경로를 연결한다. 기존 객체·컴포넌트 안에서 이 책임을 구현할 수 있다.
- 서버 권한 게임에서 클라이언트가 보낸 명중·거리·보상을 그대로 확정하지 않는다. 발사 속도·탄약·생존·매치 상태 등 해당 규칙의 검사를 권한 측에 둔다.
- 지속 상태, 요청, 순간 효과를 구분한다. 지연 참가자가 현재 상태를 복원할 수 있어야 한다.
- Reliable 전송을 전역 순서, 영구 보관, 게임 규칙의 정확히 한 번 실행 보장으로 확대 해석하지 않는다.
- 사망·보상·완료처럼 중복에 민감한 전이는 기존 상태나 요청 식별로 처리 범위를 정한다.

## 시간과 지연 대응

| 개념 | 다루는 문제 |
| --- | --- |
| 보간 | 받은 과거 상태 사이의 표시를 부드럽게 함 |
| 외삽 | 새 상태가 없을 때 이후 상태를 추정 |
| 입력 예측 | 확정 결과를 기다리는 동안 로컬 입력을 시뮬레이션 |
| 보정·재시뮬레이션 | 확정 상태와 입력 기록을 기준으로 예상 상태를 다시 맞춤 |
| Lag compensation | 규칙이 허용하는 과거 시각의 상태로 판정 |

렌더 프레임, 물리 업데이트, 시뮬레이션 tick, 전송 간격, 서버 시각, 보간 지연을 구분한다. 시각적 부드러움만으로 권위 상태 일치를 증명하지 않는다.

재시뮬레이션 때 소리·보상·탄환 생성·저장 같은 일회성 효과가 반복되지 않게 한다. 채택한 엔진의 기존 예측 기능과 상태를 이중 관리하지 않는다.

과거 판정에는 사용할 시간, 이력 범위, 허용 상한, 대상, 현재 상태 복구, 공격자·피격자의 공정성 규칙이 필요하다. 특정 엔진 예제의 tickrate나 이력 시간을 모든 게임의 기본값으로 옮기지 않는다.

## 연결과 객체 수명

- 플레이어 정체성, 현재 연결, Pawn/NetworkObject, 매치를 구분한다. 재접속 뒤 오래된 연결의 결과를 새 상태에 적용하지 않는다.
- 생성·동기화 준비·Despawn·파괴·Scene/World 전환의 경계를 확인한다.
- 다른 객체·변수의 도착 순서를 근거 없이 가정하지 않는다.
- 필요한 관찰자·전송 빈도·변화량을 선택한다. 모든 상태를 매 프레임 전송하는 형태부터 시작하지 않는다.

관련 변경의 확인 상황을 고른다: 원격 Client, 전용 서버, 지연 참가, 동시에 여러 명 사망, 예약 중 연결 종료, 지연·손실·순서 변화, 장면 전환, 예측 재실행. 매번 전 항목을 의무 테스트로 요구하지 않는다. 로그에는 문제에 필요한 역할·객체·연결·tick/요청 식별을 남긴다.
