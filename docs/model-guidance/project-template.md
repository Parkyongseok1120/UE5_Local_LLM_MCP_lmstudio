# 프로젝트 현황 템플릿

적용: 실제로 확인한 현재 프로젝트만 기록한다. 빈칸·예시를 사실로 주입하지 않는다. 모든 항목을 채워야 작업을 진행할 수 있는 양식은 아니다.

## 식별과 범위

- 프로젝트 식별자·루트:
- 확인한 커밋/파일 상태·날짜:
- 엔진·언어·실제 패키지 버전:
- 네트워크 방식·실행 대상:
- 현재 요청과 수정 가능 범위:
- 프로젝트 규칙·사용자 선호:

## 기존 소유자와 연결

| 사실·기능 | 설정/정의 | 실행 상태의 결정권자 | 변경 시작점 → 소비자 | 종료·복구 책임 | 소스 근거 |
| --- | --- | --- | --- | --- | --- |
| 해당 작업에 필요한 항목만 기록 | | | | | |

각 소유자·경로는 “확인됨”, “연결 누락”, “미확인”, “제안”을 구분한다. 원하는 구조를 현재 구현인 것처럼 적지 않는다.

## 유지할 계약과 확인할 결함

- 유지해야 하는 입력·결과·실패 의미:
- 확인한 결함과 조건:
- 재사용할 기존 기능:
- 에셋·인스펙터·Blueprint·맵·패키지 등 별도 확인이 필요한 연결:
- 관련 작업의 확인 방법과 아직 실행하지 않은 것:

일반 SSOT/SOLID 설명은 복사하지 않고 주제 문서를 참조한다. 프로젝트 전환 시 이 문서는 새 프로젝트에 재사용하지 않는다. 관련 코드·버전·설정이 바뀌면 해당 사실을 다시 확인한다.
