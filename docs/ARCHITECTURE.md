# 시스템 구성과 처리 흐름

이 도구는 검색, 파일 작업, 대화 압축을 나눠서 처리합니다. 기본 방식인 `Direct`에서는 AI가 무엇을 찾아보고 언제 수정할지 정합니다. 서버는 요청한 작업을 수행할 수 있는지 확인하고 결과를 돌려줍니다.

| 구성 | 하는 일 |
|---|---|
| `unreal-rag` | 엔진·프로젝트 자료 검색, 함수·클래스 조회, 기본 프로젝트 선택, 검색 자료 갱신과 상태 확인 |
| `unreal-agent` | 파일·로그 읽기, 부분 수정, 새 파일 생성, 승인된 삭제, 코드 진단, 빌드와 테스트 |
| `codex/unreal-context-compactor` | 긴 대화에서 오래된 내용을 줄이고 현재 요청·작업·파일·검사 결과를 남깁니다. 기본 `OFF`. |
| `unreal-agent-strict` | 선택 기능입니다. 대화별 시작과 종료를 관리합니다. |

## 자료 검색과 답변 생성 흐름

수집기가 코드와 문서를 읽어서 `raw_*.jsonl`을 만듭니다. `build_rag_index.py`가 엔진별 `rag.sqlite`에 넣습니다. `unreal_rag_direct.py`는 선택한 프로젝트와 맞는 자료에서 필요한 부분을 찾아 반환합니다.

현재 기본 목록은 검색 쪽 8개, 파일·실행 쪽 20개 도구입니다. 정확한 목록은 [stable_tool_manifest.json](../config/stable_tool_manifest.json)과 실행 중인 서버의 `tools/list`를 기준으로 확인해야 합니다.

프로젝트 자료에는 이름과 실제 경로를 함께 기록합니다. 다른 위치에 있는 같은 이름의 프로젝트는 별개입니다. 엔진 버전이 다른 자료는 한 번의 조회에서 섞지 않습니다.

## 파일 상태 확인과 저장 절차

읽기 결과에는 `fileVersionReceipt`가 들어 있습니다. 어느 프로젝트의 어느 파일 상태를 읽었는지 확인하는 표식입니다. 기존 파일을 수정할 때마다 이 값이나 현재 SHA-256인 `expectedHash`를 직접 전달합니다. 성공한 수정 결과는 다음 수정에 쓸 새 표식을 줍니다. 서버가 같은 대화의 값을 자동으로 고르지는 않습니다.

실제 쓰기 전에는 허용된 경로인지, 다른 작업이 내용을 바꾸지 않았는지 확인합니다. 경로별 잠금으로 겹치는 작업을 조정하고, 두 파일 묶음 수정은 사전 확인과 복구 기록을 사용합니다. 이 확인이 같은 사용자 권한의 다른 프로그램이 마지막 순간에 경로를 바꾸는 모든 경우까지 막는 것은 아닙니다.

## 빌드와 테스트

빌드와 자동화 테스트는 같은 실행 관리 코드를 사용합니다. 출력은 정해진 양만 보관하고, 시간이 초과되면 자식 프로세스까지 종료합니다. 저장된 로그도 앞뒤 일부만 남아 있을 수 있으므로 생략 표시를 확인해야 합니다.

`target=Editor`는 선택한 프로젝트의 기본·설정된 우선·유일하게 발견된 사용자 지정 에디터 대상으로 해석합니다. 다른 대상을 직접 지정했다면 바꾸지 않습니다.

## 대화 압축과 별도 세션 관리

압축기는 설치만으로 켜지지 않습니다. 채팅의 단일 스위치를 사용자가 켰을 때만 동작합니다. 오래된 파일 관찰에는 실제 경로와 해시를 남기되 다시 읽어야 한다는 표시를 붙입니다. 수정에 쓰는 임시 표식을 오래 보관해서 재사용하지 않습니다. 다음 도구나 완료 여부도 정하지 않습니다.

별도 `strict-server.js`는 `strict_begin`으로 시작하는 대화를 관리합니다. 기본 Python 검색 서버와 세션이나 권한을 공유하지 않습니다. 기본 서버를 환경변수로 이 방식으로 전환하는 구조가 아닙니다.

사용 규칙은 [도구 사용 규칙](LMStudio_MCP_Tool_Discipline.md), 권한은 [SAFE·AGENT 설명](Safe_Agent_Mode.md)에 있습니다.
