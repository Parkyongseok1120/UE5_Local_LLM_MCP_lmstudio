# v1.4.0-RC4 변경 사항 (초안)

이번 변경은 [하네스·컴팩터·MCP 점검 보고서](Harness_Compactor_MCP_Audit_20261016.md)에서 확인한 세 가지 문제를 대상으로 합니다.

- 압축 과정에서 이전 대화가 사라지는 문제
- 공유 예산이 부족하다는 이유로 도구 호출이 거부되는 문제
- 응답이 중단된 뒤 "계속"이라고 지시해도 작업이 이어지지 않는 문제

## 주요 변경 사항

### 이어하기와 중단 후 재개

- "계속해줘", "계속해서 진행해", "이어서 해줘", "마저 해줘", "go ahead" 같은 짧은 지시를 이어하기로 인식합니다. 이전 목표와 결정 노트를 그대로 유지합니다. 다만 "계속 실패하는 원인 찾아줘"처럼 새로운 대상을 가리키는 요청은 새 목표로 처리합니다.
- 사용자가 생성을 중단해도 그때까지 채택된 continuity 노트를 저장합니다.
- 중단 직전에 반환된 도구 결과가 다음 턴의 압축 과정에서 빠지지 않도록 보존합니다. 이전에는 이 상황에서 턴 전체가 실패했습니다.
- 과거 메시지 하나를 편집해도 이후 대화의 내구 복원이 영구히 꺼지지 않습니다. 경계 키가 바뀌거나 서명이 맞지 않으면 복원 범위만 부여하지 않고, 대화 자체는 계속 사용할 수 있습니다.
- 창(window) 복원 실패의 원인을 구분해 기록합니다(`no_window_file`, `window_parse_failed`, `source_prefix_mismatch`와 첫 불일치 위치 등). 접두부 식별값은 호스트가 블록을 저장하는 방식(병합·분리)과 관계없이 일치합니다.
- 보관 기한을 24시간에서 7일로 늘렸습니다. 봉인된 창이 참조하는 근거는 기한이 지나도 복원할 수 있어, 다음 날 이어서 작업할 수 있습니다.
- 생각 단계에서 출력 상한에 걸리면, 재시도는 여유 공간이 허락하는 범위에서 상한을 두 배로 늘려 진행합니다.

### 압축 보존

- 압축할 때 최근 1~2개 턴을 원문 그대로 유지하는 후보를 먼저 시도합니다.
- 직전 최종 답변(중단된 턴이면 마지막으로 보이는 진행 내용)의 앞뒤 3,000자를 assistant 근거 블록에 보존합니다. 필수 하한까지 압축하는 경우에도 유지합니다.
- 압축으로 빠진 사용자·어시스턴트 대화문을 아카이브(`conversation://user`, `conversation://assistant`)에 보관합니다. `evidence_first_read_context`로 다시 읽을 수 있습니다.
- 압축 임계값이 로드된 컨텍스트 크기에 맞춰 커집니다(`Working input scaling`: Auto가 기본, 기존 동작은 Fixed). 필수 하한 위로 작업 공간 6K 토큰을 확보합니다.
- 의미 요약 호출(semantic handoff)은 기본값이 Off입니다. 기록된 실행에서 한 번도 채택되지 않았고, 매번 시간 제한까지 대기했기 때문입니다.

### 도구 호출 예산

- 읽기 결과 예약을 바이트 기준에서 추정 토큰 기준(UTF-8 2.5바이트당 1토큰)으로 바꿨습니다.
- 다음 라운드의 출력 예약을 두 번 차감하지 않습니다. 이제 38,912 컨텍스트에서도 기본 읽기 두 개를 한 배치로 실행할 수 있습니다.
- 예산 안내와 반복 읽기 관찰은 대화 기록에 남기지 않습니다. 해당 실행 동안만 모델 입력의 실행 데이터로 전달합니다.

### 성능

- 노트·작업 진행 상황·실행 데이터를 system 바로 뒤가 아닌 최신 사용자 메시지 바로 앞에 둡니다. 따라서 이 값이 바뀌어도 이전 턴의 KV 캐시 접두부가 유지됩니다.
- 단계별 토큰 측정은 선택된 입력에 대해서만 하며, 측정 캐시를 실행 단위로 공유합니다.
- 경계 키를 캐시하고 아카이브 전체 검색 결과를 기억해, 매 라운드 발생하던 동기 파일 I/O를 줄였습니다.
- 아카이브 잠금은 짧은 경합이 생기면 재시도합니다. 30초 넘게 남아 있는 잠금 파일은 PID가 재사용된 경우에도 회수합니다.
- 비제한 모드에서도 기본 60라운드 뒤에는 수집한 근거로 보고하고, 반복 읽기 경고가 두 번 나오면 일시 정지합니다.

### 단일 원천(SSOT) 정리

- 숫자 설정의 기본값·범위를 `config-defaults.ts` 한 곳에서 관리합니다.
- 프롬프트 전처리기와 실행 핸들러가 같은 방식으로 모드를 판정합니다.
- 도구 효과(읽기·변경 등)를 `config/stable_tool_manifest.json`에서 관리합니다. 컴팩터의 관찰 도구 목록과 읽기 예산 기본값은 이 파일에서 생성하며(`npm run toolcontract:build`), 서버 카탈로그와의 일치를 테스트로 확인합니다.
- 노트 복원·저장은 `NotePersistence`가, 종료 시 창 봉인은 `sealAndRelease`가 전담합니다.

## 알려진 한계

- MCP 서버 응답 계약 변경(기본 응답 상한, compact JSON, `search_files` 취소, RAG 읽기 병렬화, 도구 설명 압축)은 별도 작업으로 진행 중입니다.
- 체크포인트의 assistant 근거 메시지는 기존 저장 형식과의 호환을 위해 system 바로 뒤에 그대로 둡니다.
- `prediction-loop.ts`의 telemetry 블록 분리는 아직 남아 있습니다.
- 실제 LM Studio에서의 지연·복원률 개선은 live 측정으로 확인해야 합니다.
