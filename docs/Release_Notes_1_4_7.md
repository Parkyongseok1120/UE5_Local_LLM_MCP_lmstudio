# v1.4.7 변경 사항

**v1.4.7을 마지막으로 업데이트와 유지보수를 종료합니다.**

실제 LM Studio 대화를 보면서 긴 작업을 이어갈 때 생긴 문제를 고쳤습니다. 보고서 뒤에 “계속해줘”라고 했을 때 앞 내용을 못 이어받는 문제, C++ 코드에 백슬래시가 잘못 들어가는 문제, 한글 Windows에서 빌드 오류가 깨지는 문제를 손봤습니다.

## 이어쓰기와 파일 편집

- 긴 보고서를 받은 뒤 "계속해줘"라고 하면 마지막 안내문에 가려졌던 보고서 본문을 이어받습니다.
- C/C++ 편집에서 문자열·주석 밖에 `\t`, `\n`, `\r`이 글자 그대로 들어가는 쓰기를 거부합니다(`ESCAPED_WHITESPACE_IN_CODE`). 따옴표가 모두 백슬래시로 이스케이프된 줄도 거부하고 고친 줄을 안내합니다(`ESCAPED_QUOTE_IN_CODE`).
- 줄 범위 편집의 새 내용에 읽기 결과의 줄번호 구분 탭이 섞여 들여쓰기가 한 단계 밀리는 경우를 거부하거나 변경 내역에 경고로 표시합니다(`SEPARATOR_TAB_IN_NEW_TEXT`).
- `oldText`가 백슬래시 한 단계를 벗겨야 맞는 경우, 해당 줄과 현재 범위를 진단으로 돌려줍니다. 파일 버전 증표가 빠진 경우에는 현재 파일에서 수정 대상을 확인할 수 있을 때 다시 보낼 값을 알려 줍니다.
- 묶음 수정의 `patches[]` 안쪽 항목이 형식 검사에서 거부되면 어느 항목에 무엇이 빠졌는지 알려 줍니다.
- 줄 범위 읽기의 결과 크기를 그 범위의 추정치까지 올려, 작은 예산 때문에 한 줄씩 모자라게 돌아오던 문제를 줄였습니다.

## 빌드와 검색

- 한국어 Windows의 MSVC 출력이 깨지던 구간을 시스템 코드 페이지로 복원하고, 출력 상한으로 잘린 앞뒤 부분을 따로 해석합니다.
- 오류마다 관련 note와 소스 줄을 같은 진단에 붙이고, 소스 줄의 백슬래시를 그대로 보존합니다.
- include 존재 검사가 파일 기준 상대 경로와 `Build.cs`의 리터럴 include 경로를 해석합니다. 조건부·주석 안의 include는 경고로 낮췄고, 빌드 사전 검사는 이번 실행에서 새로 넣은 include만 차단합니다.
- `search_files`가 프로젝트 루트에서 `Source`를 먼저 탐색하고, 제외된 폴더와 중단된 검색을 구분해 보고합니다.
- 작업 공간 밖에 있는 프로젝트의 빌드 로그를 그 프로젝트의 `Saved/Logs`에 기록합니다.

## 수정 요청과 결과 확인

- 답변에서 수정이나 빌드를 끝냈다고 했는데 도구 결과로 확인되지 않으면 안내를 붙입니다.
- "응", "진행해" 같은 짧은 승인을 직전 답변의 분명한 수정 제안에 연결합니다. 승인된 수정이 글로만 끝나면 한 번 수정 도구로 돌아갑니다.
- 같은 도구가 반복해서 실패하면 원인을 안내합니다.

## 설치·업데이트

- `Evidence-First-Integrated-v1.4.7.zip`과 함께 제공되는 `.sha256` 파일을 내려받아 ZIP 해시를 확인합니다.
- ZIP을 보관할 폴더에 압축을 풉니다. 설치 후에도 이 폴더에서 도구를 실행합니다.
- Windows 신규 설치는 `INSTALL.bat`, 같은 폴더에서 기존 연결을 갱신할 때는 `UPDATE.bat`를 실행합니다.
- Ubuntu와 Apple Silicon macOS는 `./install.sh`를 실행합니다. Intel Mac은 Linux x64 VM에서 llmster/LM Link를 사용하는 `--headless-lmlink` 절차를 따릅니다. [설치 안내](Integrated_Installer.md)
- 설치·업데이트 후 LM Studio를 완전히 종료했다가 다시 실행합니다.

## 확인하지 못한 범위

자동 테스트와 문제 대화의 재현으로 수정 내용을 확인했습니다. 실제 모델로 긴 작업을 다시 돌려 수정 전후를 비교하는 검증은 남아 있습니다. 프로젝트를 만들면서 측정한 수치는 [README의 검증 결과](../README.md#확인한-결과)에 정리했습니다.
