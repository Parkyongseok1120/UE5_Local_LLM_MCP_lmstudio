# 평가 신뢰성·읽기 안내 보정 실행 기록

기준 커밋: `bc5e92b33fbdd380093add6e432b331eba4da52d`. 사용자 승인 후 구현한 후속 작업이다. 원래 Claude 작업 트리와 기존 78건 평가 원본은 보존한다. 커밋·푸시는 하지 않는다.

## 적용한 변경

- 기존 엔진 지침 전달 수정본을 재사용한다. 이전 턴의 설치 엔진 관찰을 현재 입력에 연결하되, 프로젝트 전환·다른 프로젝트의 반환·descriptor 변경·버전 충돌·복원된 창의 우선권을 유지한다. 전체 과거 관찰과 엔진만 남긴 후보의 프로젝트·버전이 다르면 과거 관찰을 적용하지 않는다.
- 가이던스 예산이 부족할 때 선택한 최소 지침을 먼저 유지하고 부가 데이터를 생략한다. 새로운 의미 판정기나 완료 판정 저장소는 만들지 않는다.
- 암묵적 전체 읽기를 거부할 때 기본 제안을 `read_file_range(1,20)`에서 `search_files`의 `argsTemplate`으로 바꾼다. 검색어는 호출자가 채운다. 정규화·MCP 직렬화에서도 템플릿을 보존한다. 명시적 byte window, 실제 잘림의 다음 페이지, 파일 찾기 실패 및 편집 복구 제안은 기존 계약을 따른다.
- Compactor **0.4.80 / revision 127**, Unreal MCP **0.3.29**, 설치 구성 **2.1.29**. 제품 전체 버전은 1.4.0을 유지한다.

## 새 평가의 계약

`eval-ue-accuracy.cjs` 출력 스키마는 **3**이다. 기존 78건 결과를 새 평가에 이어 붙이지 않는다.

1. 사례별 목록·읽기 도구가 해당 사례의 파일만 노출한다. 다른 사례와 경로 우회는 거부한다.
2. 정상 hit-marker 경로의 컴포넌트 생성·GameMode 연결·표시 구현, 양쪽 lever 경로의 선택 대입, 정상 Toggle 구현을 채운다. 나머지 외부 UI·맵·입력 전제는 `CaseContext.md`에 명시한다. 이 자료는 **소스 수준 발췌 평가**이며, UBT로 컴파일한 완전한 게임이나 플레이 검증이 아니다.
3. 프롬프트·평가 근거·엔진 조회를 실제 설치된 **UE 5.8.2 / CL 56702186**으로 통일한다. 실행 전에 Build.version과 각 파일 SHA-256을 검증한다. 지원되는 심볼만 실제 소스 범위를 반환하며, 모르는 심볼을 성공 처리하지 않는다. 실제 UE 5.7.4 게임에 5.8 계약을 적용하도록 버전 제한을 푸는 변경은 없다.
4. 전체 사용자 표시 답변, 도구 인자·결과·해시, 라운드 관측, 가이던스 선택, 실제 모델 설정을 로컬 원본에 저장한다. 비공개 추론 본문은 저장하지 않는다. 원본에는 소스 발췌가 있으므로 저장소에 배포하지 않고 요약·해시만 공유한다.
5. `score`와 `labelPass`는 기존 라벨 지표다. 원인·근거·심각도는 별도 축이다. 원인·근거 검토가 없으면 `pass`는 미확정이며 정답 라벨 자체가 사실 검증을 대신하지 않는다. 모델 출력에 검토 성공 필드를 넣어도 검토 점수를 얻지 못한다.
6. P7은 후속 턴도 실제로 실행해 기록한다. `not_defect`만으로 철회·재등장 없음·자기 교정을 성공 처리하지 않는다. 별도 검토가 없으면 미관측 상태를 유지한다.
7. 빌드·fixture·runner·모델·컨텍스트·템플릿·사례·시드 설정이 다르면 재개를 거부한다. 실제 예측 설정도 비교한다. 하네스가 의도적으로 바꾸는 출력 상한은 요청값과 반환값의 일치를 따로 확인한다. 원본 파일이 있으면 기본 실행은 덮어쓰지 않으며, 출력 잠금과 임시 파일 교체를 사용한다.
8. 시드는 요청값이다. 런타임이 유효 시드를 반환하지 않으면 그 사실을 기록한다. temperature 0이나 시드 차이만으로 결정론 또는 개선 원인을 주장하지 않는다.

## 실행 중 확인한 경계

첫 보정 smoke의 정상 Client RPC(P1-N)는 정상으로 판정했고, 답변은 owning connection과 컴포넌트 생성·표시 경로를 인용했다.

P3-D는 `GetFunctionCallspace`가 Remote를 반환한다는 이유로 정상으로 오판했다. Remote라는 결과만으로 실제 송신·수신·실행이 모두 성공한다고 볼 수 없다. 평가용 조회 목록에 빠져 있던 수신 경로도 조사할 수 있도록 다음의 실제 설치 소스 근거를 추가했다.

- `DataChannel.cpp:3389` — 들어온 연결과 Actor의 연결을 비교해 `bNetOwner`를 설정한다.
- `NetDriver.cpp:8452` — 기본 `ShouldCallRemoteFunction`은 서버에서 `bNetOwner`를 요구한다.
- `DataReplication.cpp:1391` — `ReceivedRPC`가 위 검사를 통과한 뒤에만 실행을 진행한다.

**최종 소스 대조에서 초기 해석도 정정했다.** UE 5.8.2의 이 fixture에서는 `AActor::GetNetConnection` (`Actor.cpp:1965`)이 Owner가 없으면 null을 반환한다. `ProcessRemoteFunction` (`NetDriver.cpp:8263`)의 null 검사 안쪽에만 `ServerConnection` 대입이 있으므로, 클라이언트도 `:8274`의 “No owning connection” 경고로 송신 전에 중단된다. 이 경고를 서버→클라이언트 전용으로 간주했던 해석은 틀렸다. 수신 측 소유권 검사는 추가 방어 경로이며 이 사례의 첫 실패 지점은 아니다. 독립 소스 검토에서도 같은 결론을 확인했다.

수신 경로 추가 전후의 평가는 서로 다른 fixture hash로 보관하고 합산하지 않는다. 조회 가능한 근거와 도구 설명이 함께 바뀌었으므로, 라벨 변화만으로 수신 근거 추가의 인과 효과를 단정하지 않는다.

## 완료된 실모델 확인

모델은 기존에 로드된 `swift-1.5-qwen3.8-27b`를 사용했다. 모델 로드 설정은 변경하지 않았다. 실제 LM Studio SDK 추론과 제품 prediction loop를 사용했지만, 사례 도구와 controller는 합성 평가용이다. 실제 GUI 채팅·게임 MCP의 전체 감사 속도 시험은 아니다.

P7의 시간은 중립적인 최종 정리 후속 턴까지 포함한다. 철회 유지도 관찰한 후속 **1턴**에 한정한다. 마지막 P7은 `Params.Owner`를 실제 9행 대신 8행, `SpawnActor`를 10행 대신 9행으로 인용했다. 원인 설명과 정확한 인용을 구별하며, 엄격한 근거 축에서는 통과 처리하지 않았다. P3-N의 `LocalRole == ROLE_Authority` 설명은 단순 인용 오차가 아니라 실제 원인 설명 오류다.

최종 빌드 ID는 `ef-build-v2-4cf45cf9c625634b8e9b1aec4e1b526674691714427c42e4ad4edbd009b543d9`이다. 마지막 2건은 실행 전 소스/컴파일 identity 일치를 확인했다. 이전 2묶음은 중간 탐색 기록으로 유지한다. **7건을 합산한 정확도나 개선율을 제시하지 않는다.** 원본 채점의 미검토 상태를 덮어쓰지 않고, 독립 소스 검토 결과를 별도 `source-review.json`으로 저장했다.

과거 78건 원본과 새 결과는 평가 장비의 `$USERPROFILE/.evidence-first/evaluations/harness-20261019/`에 보관했다. 각 파일의 SHA-256은 근거 패킷과 해당 폴더의 `manifest.json`에 기록했다. 이 경로는 평가 기록의 위치를 익명화한 표기이며 배포본에서 접근할 수 있는 자료가 아니다. 평가 원본에는 엔진 소스 발췌가 포함되므로 저장소에는 포함하지 않는다.

## 검증·설치

검증 결과와 제한은 [근거 패킷](evidence/harness-eval-read-repair-20261019.json)에 기록한다. 패킷 형식 검증은 사실이나 전체 작업의 완료를 인증하지 않는다.

- Compactor 전체 회귀: **855 통과, 실패 0**.
- Unreal MCP 전체 회귀: **337 통과, 2 건너뜀, 실패 0**. 기존 해시 충돌·receipt·연속 편집·변경 실패 복구 검사도 포함한다.
- 설치 상태·엔진 버전·계약 관련 Python 검사: **24 통과**.
- 최종 runner/fixture 집중 검사: **12 통과**.
- TypeScript 빌드·생성 자산·빌드 identity 검사 및 `git diff --check`: 통과.
- 새 stdio 회귀에서 351행의 심볼을 검색으로 찾아 해당 범위를 읽었으며, 1행부터 읽기나 불필요한 다음 페이지 안내를 거치지 않았다. 이는 테스트 호출자가 검색을 선택한 결과이며 모델의 검색 선택률 개선을 뜻하지 않는다.
- LM Studio 설정에 등록된 실제 Node/서버 경로의 새 stdio 연결에서도 MCP 0.3.29와 `search_files` 템플릿 전달을 확인했다. 게임 소스는 수정하지 않았다.

기존 `install.py --profile custom --components context_compactor --skip-deps --skip-runtime-bootstrap --yes` 경로로 최종 빌드를 설치했다. 기존 20개 채팅의 활성화 설정은 이미 켜져 있어 변경 0건이다. 디스크 설치 검사는 정상이며 누락·불일치가 없다. 설치기는 `restartRequired: true`를 반환했고 상태 도구는 `runtimeActivationProven: false`다. **기존 GUI 채팅이 새 빌드를 로드한 상태까지 확인한 것은 아니다.** 새 MCP 연결은 검증했지만 이미 열린 연결의 재시작을 대신하지 않는다.

이번 변경은 쓰기 API를 재설계하지 않는다. 명시적 byte window와 기존 hash/snapshot/receipt, 편집 충돌 거부, 연속 편집 계약을 유지하며 관련 회귀를 통과했다.

## 다음 채택 판단

실패가 남은 원인 설명과 정확한 인용을 구별해 보완 후보를 정한다. 엔진 자료를 읽고도 클라이언트 Role을 잘못 설명한 현상을 자동 판정기 추가의 근거로 삼지 않는다. 정상/결함 13개 전체와 수정에 사용하지 않은 사례를 같은 빌드·설정으로 off/auto 비교하는 검증은 아직 남아 있다. 실제 MCP 읽기량·중복 범위와 GUI 세션 완료·종단 시간도 별도로 측정해야 한다. 이번 테스트의 편집 회귀 통과만으로 모델의 실사용 편집 효율 향상을 주장하지 않는다.

이번 합성 정확도 smoke를 실제 게임 감사 속도 개선으로 해석하지 않는다. 과거 prefix replay의 처리량 절감과 `fbff0599…` 대비 전체 작업 개선은 별도 비교다. 실제 모델 결과가 충분하지 않으면 자동 반례 판정·강제 완료 차단·새 캐시/인덱스·양자화 설정 변경을 추가하지 않는다.
