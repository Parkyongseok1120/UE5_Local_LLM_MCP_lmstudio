# v1.4.0-RC3 변경 사항

이번 시험 배포는 RC2 이후 하네스의 실행·복구·종료 흐름과 컨텍스트 압축 후 근거 복원을 보강합니다. 긴 도구 작업에서 이미 확인한 결과를 유지하고, 추가 실행이 불가능한 경우 확인된 결과와 미완료 범위를 구분해 보고하도록 개선했습니다. 설치·업데이트와 운영체제별 CI 회귀 검사도 정리했습니다.

## 주요 변경 사항

### 하네스 실행과 최종 보고

- 실행 상태에서 복구 계획과 재시도 상태를 관리하고, 입력 준비·복구 판단·최종 전달의 책임을 분리합니다. 도구 권한과 출력 예약 예산을 복구 경로에서도 유지합니다.
- 일반 실행과 평가가 같은 종료 판정 계약을 사용합니다. 알려진 정상 종료와 실제 보고문을 확인하고, 미실행 도구 요청·미완성 도구 호출·알 수 없는 종료 이유를 완료로 처리하지 않습니다.
- 추론 재시도 소진이나 입력 예산 차단 뒤에는 모델을 계속 호출하지 않고, 이미 반환된 근거로 부분 보고를 구성합니다. 사용자 취소 뒤 추가 모델 호출이나 보고 복구를 진행하지 않습니다.
- 초기화·실행·시간 초과·취소·자원 정리 경로에서 실행 결과를 한 번 기록하도록 보강합니다. 정리 과정의 오류가 원래 실패 원인을 덮어쓰지 않도록 처리합니다.
- 도구의 수락·진행·부분 결과·실제 완료를 구분합니다. 응답 전달 완료가 사용자의 전체 작업 완료를 뜻하지 않도록 상태를 분리합니다.

### 컨텍스트 압축과 근거 연속성

- 파일의 줄·UTF-8 바이트 범위와 이어 읽기 위치를 체크포인트에 보존합니다. 버전·제공자·질의 범위가 다른 관측을 합쳐 전체 확인으로 승격하지 않습니다.
- 동일 범위의 반복 읽기와 새 페이지·새 버전·현재 입력에서 사라진 근거의 재획득을 구분합니다. 버전이 없는 결과는 내용 식별값도 비교합니다.
- 보관된 근거의 원문 재조회와 페이지 읽기 계약을 보강합니다. 실제로 다음 내용을 읽을 수 없는 예산에서는 명시적인 오류를 반환하고 요청 한도와 적용된 한도를 구분합니다.
- 요약 시도의 중복·실패 재시도·누적 시간 예산을 관리합니다. 새로운 도구 호출 ID만으로 동일 근거를 새 요약 사건으로 취급하지 않습니다.
- 로드된 빌드와 디스크에 설치된 빌드를 구분합니다. 빌드 식별값에 소스·컴파일 설정·SDK 패치 입력을 반영해 업데이트 후 재로딩 여부를 확인할 수 있게 합니다.

### Unreal MCP와 Unity MCP

- 파일 생성·치환·일괄 수정의 취소와 실제 게시 시점을 구분합니다. 쓰기가 적용된 뒤의 부수 처리 실패가 적용 결과를 잘못 바꾸지 않도록 보강합니다.
- 심볼 본문 선택에서 주석·문자열·앞선 호출문을 제외하는 처리를 개선합니다. 선택된 후보와 확인 한계를 유지합니다.
- MCP 자식 프로세스의 초기화 실패·EOF·시간 초과·중단 시 정리 책임을 보강합니다.
- 에디터 메타데이터 내보내기와 RAG 갱신의 상태·결과·취소 처리를 정리합니다. 자동 검사 결과를 실제 게임플레이나 에디터 실행 성공으로 해석하지 않습니다.

### 설치·업데이트와 CI

- Windows 업데이트 실행기는 설치 시 기록된 Python 런타임을 우선 사용하며, 기존 MCP 연결을 먼저 점검한 뒤 업데이트를 진행합니다. 사용자 지정 LM Studio 경로를 압축기 업데이트에도 전달합니다.
- 설치 실패 시 대화의 플러그인 활성화와 설정 변경을 함께 복구합니다. 파일 쓰기가 실패한 대화를 갱신 성공으로 집계하지 않습니다.
- 휴대용 패키지에 필요한 새 실행 모듈과 문서를 포함하고, 공개 근거 문서의 개인 경로를 제거합니다.
- Windows 일괄 수정 테스트의 물리 경로 식별을 실제 실행 코드와 맞췄습니다. Intel Mac 설치기의 Windows 테스트는 WSL 실행기 대신 Git Bash를 명시적으로 사용합니다.
- macOS 설치 롤백 테스트의 모의 프로세스 응답을 보정하고, 기존 CI 검사와 플랫폼별 검증 범위를 유지합니다.

## 검증 범위

배포는 최종 Develop 커밋의 GitHub CI 전체 통과를 기준으로 진행합니다. Windows·Ubuntu·macOS에서 Direct MCP, Unity MCP, 컨텍스트 컴팩터, 휴대용 설치와 패키징 경로를 검사합니다. Windows에서는 전체 Python 검사·반복 실행·정적 검사와 OSS 배포 준비 검사도 수행합니다.

자동 회귀 검사는 실행 계약과 오류 복구를 검증합니다. 모델의 원인 분석 정확도, 장기 작업 성공률, 응답 속도 향상을 보증하는 수치는 아닙니다. 실제 모델 비교에서 답변 품질 유지와 불필요한 재독 감소 목표는 아직 검증을 완료하지 못했습니다. RC3 설치 후 실제 LM Studio 대화와 Unreal·Unity 에디터 동작 확인은 별도로 필요합니다.

## 설치 및 업데이트

- 첨부된 통합 ZIP을 새 디렉터리에 풀고 해당 플랫폼의 설치·업데이트 실행기를 사용합니다.
- 압축기와 MCP, 근거 검토 서버 및 프리셋을 함께 갱신하고 LM Studio에서 플러그인을 재시작해 새 빌드를 로드합니다.
- Windows 기존 설치는 `UPDATE.bat`를 사용합니다. 사용자 지정 설정은 `UPDATE.bat [path-to-mcp.json]`으로 지정할 수 있으며 `--dry-run`으로 먼저 확인할 수 있습니다.
- Unity Bridge가 다른 소스 트리에 연결되어 있으면 통합 `install.py`의 Unity 설치 경로로 연결을 이전합니다.
- 엔진 설치 경로·게임 프로젝트·RAG 인덱스는 로컬 설정을 사용합니다. 배포 ZIP에는 개인 경로나 로컬 인덱스를 포함하지 않습니다.
