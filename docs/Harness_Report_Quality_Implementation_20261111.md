## 구현

| 기존 소유자 | 변경과 계약 |
|---|---|
| `prediction-stream.ts` | 편집 허용 정렬과 줄 유사도 기반 삭제를 제거했다. 완전히 같은 보고와 그 뒤의 분리된 추가 본문에서만 앞부분을 중복 제거한다. 중간 삽입, 정정, 항목 삭제, 끝부분 삭제는 수정된 문맥 전체를 보존한다. 인라인 코드·코드 블록의 공백을 의미 없는 서식으로 합치지 않는다. 비교와 삭제 위치 계산은 같은 정규화 결과를 사용한다. |
| `review-register.ts` | 표시용 240자 발췌 전에 위치와 참조 대상을 기록한다. 기각 대상과 scope는 기각 문장 안에서 얻는다. 명시된 다른 owner에 일치하는 후보가 없으면 다른 파일로 fallback하지 않는다. 부정·조건부 해결 문구를 확정 기각으로 처리하지 않는다. |
| 같은 실행의 판단 연결 | 다른 identifier에 대한 정정은 함께 언급됐다는 이유만으로 기존 주장을 clear하지 않는다. 관련 후보는 `needs_recheck`와 정정 연결 정보를 유지한다. 보고에 연결하지 못한 경우 **판단 연결 미확인**으로 표시하고, 원래의 미검증 가설과 관련 정정을 함께 투영한다. 어느 쪽도 확정 사실로 승격하지 않는다. 명시적으로 같은 대상의 기각은 기존 상태에 반영한다. |
| `report-coverage.ts` | 미완독 파일 수만으로 일반적인 정적 추론을 거부하거나 보고 보완을 생성하지 않는다. “전량 읽었다”는 긍정형 완료 이력만 반환 기록과 대조한다. 부정·계획·의무·인용·코드 예시는 수행 주장으로 취급하지 않는다. |
| `delivery-controller.ts`, `prediction-loop.ts` | 생성한 가시 텍스트, 새로 전달한 텍스트, 중복 억제량을 구분한다. 보완의 `outputDisposition`을 delivered/duplicate_only/filtered/no_generation으로 기록한다. 새 시도 시작에서 이를 초기화하여 이전 보고의 출력 상태가 막힌 보완으로 넘어가지 않게 한다. |

새 저장소·예산 계산기·도구 스케줄러를 추가하지 않았다. ReviewRegister의 실행 수명과 영속화 정책은 유지한다. `outputDisposition`은 기존 supplement 상태에 추가되는 계측 필드다. 기존 `supplement_duplicate_suppressed.deliveredChars`는 실제 새 전달량으로 바로잡고, 과거 보고 길이는 `priorReportChars`로 분리했다.

## 회귀 기준과 반례

- `없음→있음`, severity, 숫자, 파일 경로, source version, 기각 상태의 정정을 보존한다.
- 정확한 반복은 제거하지만, 일부만 같은 보고나 기존 문장을 철회하는 중간 삽입은 문맥과 함께 남긴다.
- 코드 들여쓰기와 인라인 문자열의 공백 변경을 보존한다. 작은 fragment와 큰 fragment의 결과가 같다.
- 한 함수의 정상 판정이 호출부의 다른 결함을 지우지 않는다. 같은 이름의 다른 owner, 문장 간 scope 누출, `not fully resolved`·조건부 해결을 검사한다.
- 실제 대화의 선택된 판단 문구와 반환된 정의 위치를 최소 fixture로 재생한다. 이는 모델이 표명한 판단 상태 추적 검사이며, 게임 코드에 대한 모델 결론을 정답으로 사용하지 않는다.
- 같은 handler에서 실제 무출력, 정확한 반복, 의미 정정을 streaming/non-streaming 각각 검사한다. 이전 보고 보존, 신규 전달량, 보완 분류, 추가 연구 없음까지 확인한다.
- 필요한 부분만 읽은 감사의 정상 사례와 거짓 전량 읽기 수행 주장, 부정·계획·인용을 구별한다.

초기 구현을 독립 검토하면서 참조 동시 등장에 의한 잘못된 clear, scope fallback, 삽입문 지시 대상 유실, 인라인 코드 공백 손실, 이전 시도의 출력 분류 누출을 발견했다. 이를 회귀 사례로 추가하고 보수적인 처리로 수정했다. 특정 게임 함수명을 예외 목록에 추가하지 않았다.

## 남는 한계

자연어로 서로 다르게 설명한 두 판단이 동일한 주장인지 일반적으로 증명하지 않는다. 그 경우 기각을 강제하지 않고 연결 미확인으로 남긴다. 실제 대화의 TickServer 의심과 DisableMovement 정정도 서로 다른 주장의 가능성을 자동으로 없애지 않는다.

의미 정정 보존을 위해 수정된 보고 전체가 다시 표시될 수 있다. 이는 원문 생성량을 늘리는 정책이 아니라 이미 생성한 수정문을 버리지 않는 표시 정책이다. 기존 보고를 작은 오타만 고쳐 반복한 경우에도 오타와 판단 정정을 일반적으로 구별할 수 없으므로 숨기지 않는다.

보고 범위 검사는 제한된 수행 주장 검사이며 자연어 전체의 진실 판정기가 아니다. 필요한 관계의 실제 충분성, 모델의 결함 발견률과 반대 근거 처리, 실제 지연 개선은 별도 평가가 필요하다. target/pin/읽기 창 조정과 입력 배치 최적화의 실제 모델 비교는 완료되지 않았다.
