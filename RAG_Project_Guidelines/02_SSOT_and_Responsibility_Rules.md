# 상태 원본과 관리 책임

같은 체력이나 인벤토리를 여러 객체가 따로 고치면 어느 값이 맞는지 알기 어렵습니다. 상태마다 최종 값을 보관하고 검증하는 담당자를 하나만 두어야 합니다. 이를 SSOT라고 부르지만 답변에서는 “상태 원본”으로 풀어 써도 됩니다.

| 위치 | 맡길 일 |
|---|---|
| `GameMode` | 서버 경기 규칙·스폰·승패 |
| `GameState` | 모두에게 알려야 할 경기 상태 |
| `PlayerState` | 플레이어별 점수·팀·지속 상태 |
| `PlayerController` | 입력 전달·조종 대상·로컬 UI 연결 |
| `Pawn`·`Character` | 이동과 해당 객체 수명의 상태 |
| `ActorComponent` | 특정 액터에 붙은 기능과 그 상태 |
| `WorldSubsystem` | 월드 수명의 기능과 캐시 |
| `GameInstanceSubsystem` | 게임 인스턴스 수명의 기능 |
| `DataAsset`·설정 | 조정용 기본값 |
| `SaveGame` | 디스크에 저장할 값 |
| `Widget` | 표시와 사용자 요청 전달 |

다른 객체는 담당자에게 요청하거나 조회합니다. 내부 배열·맵을 수정 가능한 참조로 그대로 내주지 않습니다. 캐시는 원본·갱신·무효화 조건을 정하고 복제·UI 표시를 새 원본으로 취급하지 말아야 합니다.

로컬 조준이나 UI 선택에만 쓰는 `ActiveTarget`은 PlayerController에 둘 수 있습니다. 복제·리스폰 이후 유지·여러 시스템 공유·복잡한 우선순위가 필요해질 때 분리를 검토합니다.

진행률·타이머를 가진 객체와 최종 체력·잠금 상태를 가진 객체는 다를 수 있습니다. 진행 알림은 진행 담당자, 상태 변경 알림은 상태 담당자가 발행합니다. 남의 델리게이트를 직접 발행하지 말아야 합니다.
