# 설계 평가 기준

점수가 필요할 때만 책임 분리, 상태·진행 담당자, 최소 인터페이스, 요청 의도, 알림 위치, 구현 안전성, 위험 설명, 요청 범위를 평가합니다. 각 점수에는 근거와 감점 이유를 적어야 합니다.

기존 10점 기준의 상한은 다음과 같습니다.

| 문제 | 최대 점수 |
|---|---:|
| 엔진 함수가 확실하지 않습니다 | 8.0 |
| 의사코드를 컴파일 확인 코드처럼 설명 | 7.5 |
| 요청하지 않은 네트워크·대형 구조 추가 | 6.5 |
| 인터페이스에 특정 구현체 내부 기능 노출 | 7.5 |
| 상태와 진행 담당자 혼동 | 7.0 |
| 요청 계약과 상태 알림 혼합 | 7.0 |
| 검증 없는 값 설정을 안전한 요청으로 소개 | 7.5 |
| 설명과 예시의 모순 | 7.0 |

기존 설계 검토 목표는 9.2/10입니다. 숫자를 높여 적는 것으로 충족하지 말고 발견한 문제를 먼저 고칩니다. 확인이 부족한 부분은 부족하다고 적어야 합니다. 치명적인 권한·중복 상태·객체 수명·선언 오류는 총점과 관계없이 수정해야 합니다.
