# 작은 언리얼 프로토타입 설계

첫 구현은 입력, 상태 변화, 보이는 반응, 확인 방법까지 이어지는 작은 기능으로 잡아야 합니다. 필요 없는 관리자나 범용 틀을 먼저 만들지 않습니다.

현재 프로젝트의 비슷한 코드와 실제 엔진 선언을 먼저 읽습니다. 모르는 함수·모듈·태그·에셋 경로를 만들지 말아야 합니다.

상태는 원본을 가진 객체 하나를 정합니다. 다른 객체는 요청하거나 조회하고, UI는 표시와 사용자 의도 전달을 담당합니다. 조정용 DataAsset·설정값과 실행 중 변하는 값을 구분합니다.

생성자에는 기본값과 기본 구성 요소를 두고, 월드가 필요한 초기화는 적절한 시작 시점에 합니다. 타이머·델리게이트·비동기 콜백은 종료와 취소까지 함께 정합니다. Tick은 매 프레임 처리가 필요할 때만 켭니다.

블루프린트 노출은 필요한 값과 함수로 제한합니다. 멀티플레이가 요구된다면 서버 판정·복제·예측을 구분하고 저장할 값과 임시 값을 분리합니다.

코드 작성 전에는 상태 소유자, 호출 방향, 확인 방법을 짧게 적고, 작성 후 헤더·구현·모듈·객체 수명과 실제 검사 결과를 확인해야 합니다. 언리얼 코드에 네임스페이스는 웬만하면 추가하지 않습니다.
