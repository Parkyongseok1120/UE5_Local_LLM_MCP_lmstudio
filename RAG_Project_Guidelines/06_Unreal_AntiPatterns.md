# 피해야 할 언리얼 코드 패턴

한 객체에 모든 기능을 몰아넣거나 기능마다 전역 관리자를 만드는 것부터 피해야 합니다. 상태의 수명과 사용 범위에 맞는 기존 담당자를 먼저 찾습니다.

체력·인벤토리를 캐릭터와 UI가 따로 관리하지 않습니다. UI는 요청과 표시, 상태 소유자는 검증과 변경을 담당합니다. 인터페이스에 상태 변경 알림을 섞거나 외부에서 일반 값 설정 함수로 검증을 우회하지 말아야 합니다.

## 선언과 객체 수명

- `generated.h` 뒤에 include를 추가하지 않습니다.
- UObject에 일반 new·delete를 쓰지 않고 유지할 참조의 가비지 수집 추적을 확인합니다.
- 언리얼 선언 자료형에 네임스페이스를 웬만하면 추가하지 않습니다.
- `#if !UE_BUILD_SHIPPING` 같은 임의 조건 안에 `UCLASS`, `UPROPERTY`, `UFUNCTION`, `GENERATED_BODY`를 넣지 않습니다. `WITH_EDITOR`, `WITH_EDITORONLY_DATA` 등 지원되는 조건과 구현부 분리를 확인합니다. 관련 코드: `UHT_MACRO_IN_CONDITIONAL_BLOCK`.

## 객체 수명·월드 접근·반복 조회 문제

Tick에서 전체 액터·에셋을 매번 검색하지 말아야 합니다. 필요한 시작 시점의 조회, 알림, 타이머, 담당 객체의 목록을 검토합니다.

종료 뒤 콜백이 실행되거나 중복 연결되지 않도록 연결·해제를 짝짓습니다. 비동기 작업이 객체보다 오래 살면 `TWeakObjectPtr`와 실행 시 유효성을 확인합니다.

생성자에서 실행 중 월드를 기대하지 않습니다. `GEngine->GetWorld()`를 공통 월드 접근점으로 사용하지 말고 소유 객체의 `GetWorld()` 또는 명시적인 `UWorld*`를 전달합니다. 관련 코드: `GENGINE_WORLD_CONTEXT`.

월드별 명령 목록을 `static TMap` 같은 전역 컨테이너에 두면 서로 다른 플레이 월드가 상태를 공유할 수 있습니다. 해당 서브시스템의 인스턴스 멤버로 두고 수명에 맞춰 정리합니다. 관련 코드: `STATIC_MUTABLE_CONTAINER_MEMBER`.

## 네트워크 상태 판정과 검증 결과 보고

클라이언트가 보상·피해량 같은 최종 상태를 마음대로 확정하지 않습니다. Multicast나 `OnRep`에서 원본 판정을 중복 실행하지 말아야 합니다.

함수·모듈·에셋 이름을 지어내거나 검증하지 않은 예시를 실제 성공 결과로 소개하지 않습니다. [자주 잘못 쓰는 함수](Unreal_Programming/20_Unreal_API_Hallucination_Blocklist.md)를 참고해야 합니다.
