# 셰이더·머티리얼·블루프린트 분석

먼저 코드 컴파일 오류인지, 화면 결과가 다른지, 에셋 연결 문제인지 구분해야 합니다. 오류가 있다면 로그, 에셋 자료, 관련 C++·셰이더 파일을 연결해서 읽습니다.

셰이더는 `.usf`, `.ush`, 등록 코드, 가상 경로 연결, 플러그인 로딩 시점을 확인합니다. `RenderCore`, `RHI`, `Renderer`, `Projects`, `ShaderCore` 같은 모듈은 실제 사용 근거 없이 추가하지 않습니다. 렌더 스레드 작업과 게임 스레드의 UObject 접근을 구분합니다.

화면 캡처는 읽을 수 있는 노드·텍스처·매개변수·연결만 사실로 적습니다. 그 역할에 대한 해석과 가려진 부분은 따로 표시해야 합니다. 머티리얼의 부모·혼합 방식·셰이딩 방식과 내보낸 자료를 함께 비교합니다.

블루프린트 함수 호출은 `function_reference`, 변수 접근은 `variable_reference`나 실제 보이는 노드를 근거로 삼습니다. C++ 함수가 존재한다고 블루프린트에서 호출한다고 단정하지 않습니다.

답변에는 확인한 사실, 가능한 해석, 매개변수·텍스처, 모르는 부분, 추가로 읽을 파일을 적습니다. 텍스트 수정·에셋 저장·셰이더 컴파일·에디터 실행 확인을 구분해서 보고해야 합니다.
