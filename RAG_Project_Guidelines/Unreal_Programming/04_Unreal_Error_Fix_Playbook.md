# 컴파일·링크 오류 해결 절차

실제 오류가 가리키는 파일을 읽고 첫 유효 원인부터 고쳐야 합니다. 같은 원인에서 파생된 오류를 각각 다른 문제처럼 수정하지 않습니다.

## 포함 파일 탐색 오류

`C1083`이면 헤더 경로와 이를 포함한 파일을 확인합니다. 헤더를 소유한 모듈을 찾고 현재 `Build.cs`에 필요한 의존성이 있는지 확인해야 합니다. 공개 헤더에서 쓰는지 구현 파일에서만 쓰는지도 구분합니다. 생성 파일이나 플러그인 파일이라면 해당 생성·활성화 상태를 확인합니다.

## 함수 구현 누락과 링크 오류

`LNK2019`·`LNK2001`이면 선언과 구현이 모두 있는지, 반환형·매개변수·`const`가 같은지 확인합니다. 정적 멤버 정의, 모듈 의존성, 모듈 외부 공개 매크로, 실제 빌드되는 폴더인지도 확인합니다. 같은 모듈의 빠진 함수 구현을 `Build.cs`에 모듈을 추가하는 방식으로 고치지 말아야 합니다.

## 생성 헤더와 UHT 오류

`generated.h`가 마지막 include인지, 파일명과 맞는지, 앞에서 선언 문법이 깨지지 않았는지 확인합니다. UHT에 필요한 구조체·열거형의 전체 정의를 포함했는지도 봅니다. 생성된 헤더를 직접 고치지 말아야 합니다.

파일 이름 변경 뒤 남은 자료가 의심되더라도 원본 오류를 먼저 확인합니다. 생성 폴더 삭제가 필요하면 사용자가 허용한 정리 범위 안에서만 처리합니다.

## 모듈과 에디터 전용 코드

`.uproject`, `.uplugin`, `Target.cs`, `Build.cs`에서 실제 모듈 이름과 활성화 상태를 비교합니다. 에디터 전용 헤더를 실행용 모듈에 넣지 말아야 합니다. Live Coding 결과만으로 전체 빌드가 맞다고 판단하지 않습니다.

수정 후에는 해당 엔진의 UBT 결과를 확인합니다. 빌드를 못 했다면 실행할 명령과 남은 조건을 적어야 합니다.
