# 시퀀서 대상 연결과 재생 후 상태

시퀀서가 끝나면 위치가 돌아가거나 다른 액터를 움직이는 문제는 대상 연결과 종료 설정부터 확인해야 합니다. 관련 LevelSequence 에셋, 내보낸 트랙·바인딩, 실제 엔진 선언을 근거로 삼습니다.

| 이름 | 뜻 |
|---|---|
| `AActor::Tags` | 게임 객체에 붙인 태그이며 시퀀서 바인딩 태그와는 별개입니다. |
| 바인딩 태그 | 시퀀스 안의 대상 연결을 찾는 이름입니다. |
| `Possessable` | 이미 존재하는 대상을 연결합니다. |
| `Spawnable` | 시퀀스가 생성하는 대상입니다. 생성·파괴와 소유 설정을 함께 확인합니다. |
| 바인딩 재지정 | 실행 중 연결 대상을 바꿉니다. `FMovieSceneObjectBindingID` 등 실제 API를 확인합니다. |
| 동적 바인딩 | 시퀀스·디렉터 쪽에서 대상을 결정하는 구조입니다. |
| `Keep State` / `Restore State` | 종료 후 애니메이션한 상태를 남길지 복원할지 정하는 설정입니다. |

## 시퀀스 종료 후 위치와 상태 유지

어느 트랙이 누구의 Transform을 바꾸는지 먼저 확인합니다. 대상 종류와 섹션·시퀀스 종료 설정을 보고 설정만으로 해결되는지 검토해야 합니다. 재생 종료 후 무조건 텔레포트하는 코드를 먼저 추가하지 않습니다.

캐릭터라면 위치뿐 아니라 이동 모드, 충돌, 시선 제어도 확인해야 합니다. 코드 복원이 필요하면 종료·최종 상태 확보·이동·충돌·시선 복원의 순서를 실제 실행 흐름에 맞춰 정하고 로그로 확인합니다.

`bRestoreState`를 공개 필드라고 가정하거나 `SetRestoreState`, `SetBindingTag`, `AddBindingOverride`를 확인 없이 사용하지 말아야 합니다. `FMovieSceneSequencePlaybackSettings`와 실제 선언을 읽습니다. `MovieScene`, `LevelSequence` 의존성도 실제 사용 근거가 있을 때만 추가합니다.

답변에는 대상 종류, 태그와 연결의 차이, 확인한 설정·함수, 모르는 부분, 실제 검증 수준을 적습니다. 코드 제안만 했다면 `Proposed`입니다.
