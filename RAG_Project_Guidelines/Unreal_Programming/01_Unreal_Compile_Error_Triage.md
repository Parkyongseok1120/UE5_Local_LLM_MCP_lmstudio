# 컴파일 오류 분류와 진단 순서

오류가 난 줄과 주변 로그부터 읽어야 합니다. 함수나 모듈 이름을 추측해서 고치지 않습니다.

| 증상 | 먼저 확인할 것 |
|---|---|
| `C1083`, 포함 파일을 못 찾습니다 | 실제 헤더 경로, 소유 모듈, `Build.cs` |
| `LNK2019`, `LNK2001` | 함수 선언과 구현, 자료형 일치, 모듈 연결 |
| `generated.h` 오류 | 헤더 이름, 마지막 include 위치, 앞선 UHT 오류 |
| UHT가 자료형을 모릅니다 | 선언 매크로, 전체 정의가 필요한지, 모듈 의존성 |
| 실행 중 충돌 | 실제 로그, 호출 경로, 객체 수명 |

공개 헤더에서 다른 모듈의 자료형을 노출하면 `PublicDependencyModuleNames`, 구현 파일에서만 사용하면 `PrivateDependencyModuleNames`를 검토합니다. 무작정 모듈을 추가하지 말아야 합니다.

`generated.h`는 해당 헤더의 마지막 include로 둡니다. `LNK2019`는 우선 구현이 존재하는지 확인하고, 구현이 있다면 선언과 모듈 연결을 확인합니다. UHT는 C++의 전방 선언만으로 충분하지 않을 수 있습니다.

답변에는 오류 종류, 근거 파일·로그, 최소 수정, 남은 확인을 적어야 합니다. 상세 내용은 [오류 수정 안내](04_Unreal_Error_Fix_Playbook.md)에 있습니다.
