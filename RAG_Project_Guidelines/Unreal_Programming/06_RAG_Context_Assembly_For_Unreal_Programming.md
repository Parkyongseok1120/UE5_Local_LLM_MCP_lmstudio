# AI 코드 작업에 필요한 근거 수집 기준

자료를 많이 넣기보다 현재 요청을 판단하는 데 필요한 파일·선언·로그를 골라야 합니다. 현재 파일과 최근 변경이 예전 계획보다 우선합니다.

| 요청 | 필요한 근거 |
|---|---|
| 기존 코드 수정 | 현재 대상 파일, 최근 변경, 관련 호출부, 직전 실패 결과 |
| 새 코드 작성 | 실제 자료형 선언, 포함 헤더, 모듈, 현재 프로젝트의 비슷한 구현 |
| 컴파일 오류 | 정확한 오류 줄, 함수 선언·구현, 현재 `Build.cs` |
| UHT 오류 | 해당 헤더, 매크로, 생성 헤더 위치, 참조 자료형 전체 정의 |
| 실행 오류 | 실제 로그·호출 경로, 초기화·종료 시점, 객체 소유자 |
| 함수 사용법 | 실제 함수 선언, 헤더와 모듈, 짧은 호출 예시 |

이미 존재하는 함수·입력 연결·설정은 다시 추가하지 않습니다. 직전 오류가 한 가지 누락을 가리키면 전체 구현을 다시 쓰지 말고 그 부분만 고칩니다.

이 표는 근거를 고르는 기준입니다. 기본 Direct 도구에 고정된 호출 순서나 정적 검사 선행 조건을 추가하지 말아야 합니다. 실제 빌드가 필요하면 모델이 바로 선택할 수 있습니다.
