# 언리얼 코드 구현 점검

설계 설명용 의사코드와 실제 구현을 구분해야 합니다. 작성한 코드라도 실제 빌드 결과 없이 컴파일 성공이라고 적지 않습니다.

- 헤더의 부모·매크로·`GENERATED_BODY()`와 마지막 include인 `generated.h`를 확인합니다.
- 함수·변수·델리게이트·타이머의 선언과 구현·호출부를 맞춥니다.
- 블루프린트 이벤트의 `_Implementation`과 인터페이스 호출 방식을 확인합니다.
- 필요한 include와 `Build.cs`의 공개·비공개 의존성을 확인합니다.
- 실행용 모듈에 에디터 전용 코드를 넣지 않습니다.
- 유지할 UObject 참조의 가비지 수집 추적, 약한 참조, 사용 전 유효성 검사를 확인합니다.
- 생성자·등록·시작·종료에 맞는 일을 배치하고 타이머·콜백을 정리합니다.
- 서버 판정·클라이언트 요청·복제 표시를 구분합니다.
- 에셋 경로·태그·로그 이름을 확인 없이 만들지 않습니다.
- 실패를 조용히 삼키지 말고 적절한 반환값·로그를 남깁니다.

설명에서 정한 상태 담당자와 호출·알림 이름이 코드에서도 같아야 합니다. 금지한 패턴을 예시에서 다시 쓰지 말아야 합니다. 상세 구현 점검은 [코드 작성 후 확인](Unreal_Programming/10_Unreal_Codegen_Accuracy_Gates.md)에 있습니다.
