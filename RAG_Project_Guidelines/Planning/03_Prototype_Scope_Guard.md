# 프로토타입 기능 범위와 우선순위

기본은 조작 대상 하나, 상호작용 대상 1~2종, 맵 하나, 행동 1~3개, 자원 1~3개와 최소 표시로 잡습니다. 반드시 필요한 기능은 3~5개로 줄이고 나머지는 보강할 것·나중에 할 것으로 나눕니다.

저장·성장·상점·장비·대규모 온라인·복잡한 AI·완성형 UI는 사용자 요청이나 첫 검증에 필요하다는 이유가 있을 때만 넣습니다. 조작감과 즉각 반응보다 큰 기술 구조를 먼저 만들지 말아야 합니다.

위험은 첫 주에 재미 확인을 막는 것부터 적습니다. 조작감, 반응 누락, 반복 불가, 범위 증가, 작업 순서가 우선입니다. 제품화 때의 대규모 부하·운영 문제는 따로 둡니다.

최종 계획에서 필수·첫 단계·제외 항목이 서로 충돌하지 않는지 확인합니다. “단순하게”라고 적고 기능을 열 개씩 넣거나 같은 기능을 필수와 나중 항목에 동시에 두지 않습니다.
